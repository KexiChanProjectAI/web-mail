worker parse-input fix evidence
date: 2026-07-04

root cause
- `worker/src/index.ts` spread `ForwardableEmailMessage` into a fake object before calling `parseEmail()`.
- Cloudflare `ForwardableEmailMessage` properties like `headers` are not safe to preserve via object spread.
- The reconstructed object lost a usable `headers` object, so `parseEmail()` hit `message.headers.get(...)` on `undefined`.

code changes
- `worker/src/index.ts`
  - replaced `{ ...message, raw: streamFromBytes(rawMIME) }` with an explicit plain `ParseInput` object:
    `{ headers: message.headers, from: message.from, to: message.to, rawSize: message.rawSize, raw: streamFromBytes(rawMIME) }`
- `worker/src/mail/parse.ts`
  - `parseEmail()` now accepts `ParseInput`
  - added `getHeaderValue()` so header access is normalized through `Headers` or a map-like object
- `worker/src/types/index.ts`
  - added `ParseHeaders` and `ParseInput`
- `worker/test/telegram.test.ts`
  - added regression coverage for parsing a plain object input with preserved `Headers`
