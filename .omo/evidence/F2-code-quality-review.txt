   - up: `DROP TABLE IF EXISTS telegram_deliveries; DROP TABLE IF EXISTS share_tokens;`
   - down: symmetric inverse, schema-verbatim copy of 002's CREATE statements.

     the database to the same state as before the migration. The README's rollback section (step 3) correctly

     TestFallbackExtractsHeaders). These assert REAL behavior: the fallback must return a non-empty

     resulting TextBody must carry the `[Parse Error: ...]` marker. These are observable contract assertions,
     not mock-trivia.

     (401 / 413 / 200) and JSON body shapes (status=accepted, status=duplicate, message_id != 0).

WORKER TS CODE-QUALITY ASSESSMENT
---------------------------------
1. worker/src/index.ts
   - The orchestration (collectStream → parse-local → POST raw MIME to Go → only on
     `status: accepted` write KV cache + send Telegram → swallow Telegram/cache failures without setReject)
     is sound and matches the plan's "must have" list.
   - RejectableDeliveryError is a small typed exception class that scopes the reasons that should call
     `message.setReject` (auth 401, size 413, network, timeout, 5xx-after-retry) — good separation.
   - The 5xx-retry-once logic is correctly placed in `postToIngestWithStatus` and uses two independent
     AbortControllers with 30s timeouts each.
   - The 8 console.log/console.warn/console.error calls in this file are operational observability, not debug
     noise: each one logs a specific event ("Email event received", "Email raw stream collected", "Delivering
     email to ingest endpoint", "Posting email to ingest endpoint", "Email ingested successfully",
     "Duplicate email ignored", "Ingest server returned 5xx, retrying once", "Preview cache written") with
     structured metadata. They are the production access log for the Worker.
   - Pre-existing `ctx` unused at line 150 is a public-handler-signature constraint, explicitly out of scope
     per decisions.md DEC-9.

2. worker/src/handler/fetch/index.ts
   - itty-router is the right tool here (small, no DI noise, exactly the surface we need).
   - `/email/:id?mode=text|html` is the only routed path; everything else returns 404 via `router.all('*')`.
   - 404-on-missing-mode is deliberate (Telegram buttons always set mode=text|html, so a missing mode is a
     broken-link signal). Documented in the JSDoc.
   - dao.loadMailCache handles a malformed JSON payload by returning null (logged) — graceful degradation.

3. worker/src/db/index.ts
   - Dao class is minimal: loadMailCache / saveMailCache, plus an internal `_db` accessor marked "reserved
     for tests". The shape is intentionally smaller than upstream because the upstream address-list / mail-status
     / telegram-id helpers are out of scope for this migration. The comment in the file calls this out.
   - TTL handling: `saveMailCache(id, cache, ttl)` passes `expirationTtl: ttl` only when the caller supplied
     one. The default comes from the caller (task 4: `getDefaultMailTtl(env)` → MAIL_TTL env, default 86400).
     This is correct: it lets the call site own the policy.

4. worker/src/mail/parse.ts
   - postal-mime for the parse, html-to-text for the text-derivation fallback when only HTML is present.
   - `truncateStream` is a correct TransformStream-based cap with byte-level accounting.
   - All three max-size policies (`unhandled` / `truncate` / `continue`) are implemented per upstream contract
     and exercised by tests.
   - The fallback on parse failure is "synthesize a non-empty cache" rather than throw — matches the plan's
     requirement that parse failure must not block the raw-MIME ingest.

5. worker/src/mail/render.ts
   - Two-button keyboard (`View as TXT` / `View as HTML`) pointing at `${DOMAIN}/email/${id}?mode=...` —
     exactly what the plan requires and what the existing Go `payload_test.go` used to assert.
   - HTML-escapes From/To/Subject/Date/body; labels are present; body preview ≤ 300 chars; total ≤ 3500 chars.
   - No callback_data anywhere. `link_preview_options.is_disabled = true` is set so Telegram doesn't render
     a giant preview that hides the buttons.

6. worker/src/telegram/api.ts
   - createTelegramBotAPI factory + sendMessage. The factory takes a token; no global state.
   - Error model: non-2xx HTTP, or `ok: false` in the body, both throw. The error message includes the
     description so operator logs are actionable.
   - URL shape `https://api.telegram.org/bot<token>/<method>` is the documented Telegram API contract.

7. worker/src/types/index.ts
   - Env interface lists every upstream-style field with `?` for opt-in (TELEGRAM_TOKEN, TELEGRAM_ID, DOMAIN,
     MAIL_TTL, MAX_EMAIL_SIZE, MAX_EMAIL_SIZE_POLICY) and `?` for the ingest env vars (INGEST_URL,
     WORKER_INGEST_PSK). Only `DB: KVNamespace` is non-optional — correct, because the binding name is
     pinned by upstream and the Worker would crash at deploy time without it.
   - EmailCache is type-only (no runtime value), matching the upstream contract.
   - html-to-text.d.ts is a minimal ambient declaration — necessary because the package does not ship its
     own .d.ts and `@types/html-to-text` is not on the registry. The declaration is conservative: it only
     types the `convert` function and a permissive options bag.
